The appliance release workflow no longer fails immediately after pushing its first container image. `publish-images.sh` required each `ghcr.io/<owner>/aptl-candidate/<image>` staging package to be private after the push, but a package published from a workflow inherits the visibility of the repository it runs in, so this public repository always produces public packages. Staging packages are now expected to be public, and both release scripts prove publication with an unauthenticated registry pull instead of reading or writing a visibility field: GitHub exposes no endpoint that changes package visibility, and the packages API the scripts used is not reachable with the workflow token for a user-owned package. This also drops the `PATCH ... visibility=public` call in `verify-public-images.sh`, which would have failed the public-delivery job against a nonexistent endpoint.
