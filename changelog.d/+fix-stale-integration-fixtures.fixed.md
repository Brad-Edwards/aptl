Four long-failing tests now pass, and the failure that hid three of them is easier to read. The generic base image build reported only that an image did not build; it now includes the builder's own last line, which distinguishes a missing build context from an unreachable base or a failing step. The node materialization and mixed realization tests were handing the builder a bare temporary directory, so the Dockerfiles and requirements they copy from were never present; they now stage those trees the way a real project has them. The pack adapter test stubbed `dpkg-query` with a three-field row while the query asks for five, so nothing parsed and the run failed as a backend that returned no corroboration for its declared packages. The Cortex test pinned an exact `docker exec` invocation that changed when the seed moved to a piped curl config, and now asserts that behaviour rather than its spelling. One `aptl lab start` test pinned the live port query but not the live service query, so it reconciled against whatever range was running in the checkout's own directory.
