Custom Suricata detection rules now fire as intended: they chain off the built-in Suricata rules (`86601`/`86600`) via `<if_sid>` instead of declaring a rival `<decoded_as>json</decoded_as>` parent (`303000`), which the built-in parent always won — so a network web attack now surfaces as rule `303020` ("Web attack (network)", level 10) rather than the generic `86601`. Separately, the `mcp-threatintel` `add_indicator` tool can now write to MISP: its URL templates the event id into the path (`/attributes/add/{event_id}`), and the shared MCP HTTP client sends `Accept: application/json` so MISP no longer 302-redirects the POST to its web UI.
