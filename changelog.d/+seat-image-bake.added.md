The release workflow now bakes and publishes the seat VM image. `scripts/appliance/build-seat-image.sh` installs Docker, the APTL runtime and every container image TechVault starts into a guest built from a digest-pinned Ubuntu base, so a participant's first boot resolves nothing, pulls nothing and builds nothing. `scripts/appliance/publish-seat-image.sh` pushes the disk and its config blob to `ghcr.io/<owner>/aptl-seat` as an OCI artifact and proves the result is anonymously pullable. A release only bakes when the image would actually differ: `scripts/appliance/seat-image-key.sh` digests the guest assets, container definitions, locked Python closure, participant profile and pinned base image, and an image already published under that key is retagged rather than rebuilt. The third-party image set is derived from `docker-compose.yml` rather than a hand-maintained list, and an unpinned or templated reference fails the bake.
