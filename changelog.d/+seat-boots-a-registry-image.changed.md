`aptl seat` now boots an image pulled from a container registry instead of a locally staged, signed release directory. `aptl seat start` needs no arguments: it resolves the published seat image, pulls it if the host does not already have it, overlays it and runs it. `aptl seat install`, the release directory and both trust-anchor options are gone, and `--image` points a seat at any other registry reference. `aptl seat update` adopts a newer image or rolls back to one already cached, and `aptl seat images` lists the cache and prunes what nothing selects. The appliance boundary is unchanged: the launcher materializes the exact policy bytes it binds to, and the boundary gate, host exposure checks, negative reachability probe and guest readiness observation all run exactly as before.
