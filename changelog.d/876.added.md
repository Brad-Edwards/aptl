Honest per-dimension runtime readback for dynamic composition. APTL now
advertises RAES's `dynamic-composition` artifact mechanism, verifying each
declared runtime dimension — environment, published ports, Linux capabilities,
mounts, and service listeners — by read-after-write off the realized container,
and starting a node's generic substrate from the exact availability-verified
image with `--pull=never` (never re-resolving the mutable tag). Service-listener
state is read from the kernel's per-netns socket tables via an APTL-pinned
observer that runs no container-provided binary. A node whose declared runtime
state cannot be exactly verified — or that carries undeclared excess such as an
extra port, capability, mount, or network listener beyond APTL's own init
baseline — fails closed rather than being reported realized.
