The helpers that make a built MCP server runnable outside its build tree now live in `aptl.utils.mcp_packaging` rather than inside the appliance input assembler. npm links the shared `aptl-mcp-common` package into each MCP as a symlink into the monorepo, so anything shipping an MCP has to replace that link with the real package first; that is a packaging concern and outlives the offline payload assembly it happened to sit in. Archiving stays deterministic and still refuses to carry runtime identity or credentials out of a working project.
