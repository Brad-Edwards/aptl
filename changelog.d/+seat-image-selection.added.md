The seat VM disk a reference resolves to is now sticky. A mutable tag such as `:latest` is resolved once and recorded; later starts boot that same digest until the operator adopts another, so a moved tag never changes what is running out from under them. Checking for a newer image is separate from adopting one: it is rate-limited rather than run on every start, never gates the boot path, and fails open, so a registry outage or an offline host cannot delay or prevent a seat starting. Adoption is explicit and keeps the previous disk cached, so re-selecting it is a rollback. A cleared cache re-fetches the selected digest rather than silently upgrading, and a digest-pinned reference is never checked at all. A warm start proves the cached disk from a verification stamp instead of re-hashing it, so booting does not read the whole disk first.
